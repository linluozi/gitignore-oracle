# gitignore-oracle

Explain **why** a path is ignored: the exact `.gitignore` file, line number and
pattern that decided it. It also audits rules that can never fire — such as
`!build/keep.txt` placed after `build/` — and proves each finding with real
`git check-ignore`.

Upstream: none

```
$ gitignore-oracle why build/keep.txt
build/keep.txt  IGNORED  ignored via excluded parent directory 'build' by .gitignore:3 (build/)

$ gitignore-oracle audit
root: .
rule files: 1  rules: 11  negations: 5
dead_by_parent: .gitignore:4 !build/keep.txt -> witness 'build/keep.txt' decided by .gitignore:3 build/
dead_by_parent: .gitignore:6 !vendor/needed.py -> witness 'vendor/needed.py' decided by .gitignore:5 vendor/
dead_by_parent: .gitignore:8 !docs/guide.md -> witness 'docs/guide.md' decided by .gitignore:7 docs/
```

The second line is the point: git silently refuses that re-inclusion, because it
never descends into an excluded directory. `gitignore-oracle` turns that silent
behaviour into a concrete, machine-checkable finding.

## What it does

* Parses the documented gitignore grammar: `*`, `?`, `[...]`, `**` at the
  start / middle / end, `!` negation, `/` anchoring, trailing `/`
  directory-only, backslash escapes, comments, and "trailing spaces are
  ignored unless escaped".
* Applies git's precedence: deepest `.gitignore` first, last matching line
  inside a file, `.git/info/exclude` last; an excluded parent directory ends
  the walk, so nested negations below it are unreachable.
* Reports a `Decision` with `source`, `line`, `pattern`, and the excluded
  ancestor (`via`) when that is what decided the path.
* `audit` finds negation rules that are dead for a provable reason and emits a
  witness path for each. Only literal negations (which match exactly one
  path) are reported as dead, so the claim is not a sampled guess.
* `verify` compares every decision — including provenance — with
  `git check-ignore -v -z --no-index`.

## Install and run

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[test]"

# explain one path against a work tree
.venv/bin/gitignore-oracle --root /path/to/repo why src/app.log

# machine-readable decisions; exit code 1 if the path is ignored
.venv/bin/gitignore-oracle --root /path/to/repo check build/out.txt --json

# find dead negations
.venv/bin/gitignore-oracle --root /path/to/repo audit

# differential test against the installed git
.venv/bin/gitignore-oracle --root /path/to/repo verify
```

Library use:

```python
from gitignore_oracle import GitIgnore

gi = GitIgnore(".")
d = gi.check("build/keep.txt")
assert d.ignored and d.via == "build"
print(d.source, d.line, d.pattern)   # .gitignore 3 build/
print(d.reason)                      # ignored via excluded parent directory ...
```

## Evidence (all numbers produced by `tools/run_evidence.py`)

`tools/run_evidence.py` builds 16 deterministic **real git repositories**
(real files, real nested `.gitignore` files, `git init`), enumerates every file
and directory, and compares our decision and provenance with the installed git
in one batched call per repo. Corpus is generated by `tools/gen_corpus.py`; the
JSON is `evidence/differential.json`.

| Metric | Value |
| --- | --- |
| Generated git repositories | 16 |
| Unique paths (sha256 of `seed + NUL + path`) | **2,817** |
| Files / directories | 2,545 / 272 |
| Paths matched by a rule (git) | 942 |
| ... of which ignored / re-included | 898 / 44 |
| Decision mismatches (ignored vs not) | **0** |
| Provenance mismatches (source + line + pattern) | **0** |
| Dead negation rules found | **53** (36 parent-excluded, 17 overridden by a later ignore) |
| Dead rules confirmed by `git check-ignore` | **53 / 53** |
| Engine throughput (median of 3 passes) | **11,098 decisions/s** |

Reproduce:

```bash
.venv/bin/python tools/run_evidence.py        # writes evidence/differential.json
git --version                                  # recorded in the JSON
```

The engine was also run against this repository's own work tree (2,220 paths,
including a populated `.venv`) with **0 mismatches**:

```bash
.venv/bin/gitignore-oracle --root . verify
# PASS: 2034 files + 186 dirs = 2220 paths, 2198 matched by git (2198 ignored), 0 mismatches
```

That number depends on the local virtualenv, so it is a reproducible command
rather than a fixed claim.

```bash

```

Coverage includes wildcards that must not cross `/`, all three `**` positions,
anchoring, directory-only rules, escaped `#` / `!` / `*`, a trailing space, the
parent-exclusion rule, nested precedence, `info/exclude`, and a live
differential test against git (skipped only if git is absent).

## Limitations

* `core.excludesFile` (the global ignore file) is **not** read. The differential
  harness pins `git -c core.excludesFile=/dev/null` so both sides see the same
  inputs. `.git/info/exclude` is supported.
* `core.ignoreCase` is not modelled; matching is case-sensitive like a
  case-sensitive filesystem.
* The differential corpus is generated (16 work trees), not a random sample of
  GitHub repositories. It exercises the documented grammar and nested-file
  precedence, but it cannot prove parity for every repository in existence.
* A path that does not exist is treated as a file unless `--dir` is passed or
  the path ends with `/`.
* "Dead" is only claimed for literal negations, and only for the two provable
  reasons above. A wildcard negation that happens to be shadowed for one
  witness is deliberately not reported.

## 本轮创新

Existing gitignore libraries implement matching; this project makes the
**decision itself auditable**. It is, to our knowledge in this line of work, the
first implementation that (a) returns the exact `file:line:pattern` for every
decision including negations and parent-directory exclusions, (b) proves
parity with `git check-ignore -v` on 2,817 unique paths with zero provenance
mismatches, and (c) converts git's "you cannot re-include a file if a parent
directory is excluded" rule into a static audit with git-confirmed witnesses
(53/53). The novel claim is negative and testable: those 53 negations are not
merely redundant, they are **unreachable**, and git agrees on every one.

Previously the team's ledger contains no gitignore engine, no provenance-parity
harness, and no dead-rule audit; this is a new product line, not an `-opt-lab`
variant and not an upstream mirror.
